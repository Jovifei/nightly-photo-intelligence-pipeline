## 1. 背景与目标

### 1.1 两个项目

| 项目 | 仓库 | 角色 | 现状（2026-11-14 凌晨核实） |
|---|---|---|---|
| NPI：照片解析（生产端） | `Jovifei/nightly-photo-intelligence-pipeline`（Python） | 放进一张好看的照片，解析出“这张照片怎么拍”，产出姿势事实 bundle | 契约/门禁/状态机齐全；**从未读过真实照片、从未加载/跑过模型**；姿势后端只有 `PoseBackend` Protocol + fake 后端；N2B1P 外部审查硬停 |
| App：AI 相机（消费端） | `Jovifei/ai-photography-director-app`（Kotlin） | 相机举起来，按当前场景推荐姿势库里合适的拍照姿势；用户可导入姿势、可选择姿势 | 离线流程已建，main 有姿势引导 UI + 18 条样例 bundle（合成、非权威）；真实姿势估计是 `FakePoseEstimator`；T3–T17 为 15 个 stacked draft PR（#7–#21），与 main 的对账状态未知 |

### 1.2 业主目标（原话整理）

1. **照片解析**：放进一张好看的照片，解析出角度、风格、画面摆放、手的姿势、眼睛的姿势；要能复刻：离模特多远、手弯成什么程度、眼睛看什么地方、光线从哪个地方来；显卡跑。
2. **AI 相机**：相机举起来，按当前场景分析，推荐姿势库里合适的拍照姿势；用户可导入姿势、可选择姿势。

### 1.3 运行环境（已核实）

- 主机：Windows，RTX 4070 SUPER 12GB，32GB 内存；Ollama 在跑（`qwen3.5:4b` / `qwen3.5:9b`，capabilities 均含 vision，未实测过图像输入）；Qwen3-VL-2B 权重 4.26GB 已在主机 service.py 默认路径（图片输入链路未实测）。
- 手机：OnePlus 7 Pro（Snapdragon 855）。真机验证时间与后续端侧完整验收时间均待业主安排。
- GPU 空闲窗口：每天 02:00–10:00，工作日另加 14:00–19:00；周末白天不空闲。

## 2. v1 功能需求

v1 的产品核心是：**生成“有证据的拍摄配方”，不是恢复一个看似完整的真实世界**。距离、视线、灯位不必每张图都齐全；诚实告知“人物放在画面哪里、肩胯如何转、手放在哪里、优先调整什么”，比输出一组无法证实的厘米和角度更有价值。

原图估计与复刻建议必须明确区分：前者如“左肘投影角约为某范围”“原图距离未知”；后者如“使用当前手机镜头，先让人物占画面约定比例，再微调距离”“把左手从腰线移到胸前”。后一类是可执行建议，不必伪装成已经恢复出的原拍摄参数。

| 编号 | 需求 | v1 实现口径 | 不承诺 |
|---|---|---|---|
| R1 | 单张照片出全身姿势 + 逐点置信度/可见性 | 主机 MediaPipe Pose Full（33 点）基线，**原生 Windows 主机按 CPU 路径设计**（MediaPipe Python GPU 支持仅 Ubuntu，见可行性报告 §5.1）；逐点坐标/置信度/可见性；原生拓扑保留 | 133 点（属升级项，见 §6）；精确三维角 |
| R2 | 关节角 + 手形摘要 | 关节角标注为**投影角**；手部由 MediaPipe Hand Landmarker 按需细化（每手 21 点），须保留对应人物、左右手及裁剪图返回原图的变换；两个模型冲突时保留双候选并触发审查，**不平均坐标**；小手、遮挡、握物单独验证 | 手指精确解剖角度；三维手形 |
| R3 | 视线落区 + 置信度 | 三字段分离：**头部朝向、眼睛相对相机的方向、画面内可能关注的区域**，各可独立未知；Face Mesh/虹膜只作眼部几何输入，**不直接等同视线**；OpenVINO gaze-estimation-adas-0002 为**默认关闭的可选增强**，仅在合格脸部裁剪上做方向分类，输出方向向量而非注视点；小脸、墨镜、闭眼、强侧脸拒答 | 精确注视点；“头朝左”自动等于“眼睛看画面左侧对象” |
| R4 | 距离估计 + 景别 | **构图闭环为主，米制估计为辅**：手机复刻时先固定所用镜头、匹配人物画面占比与裁切位置，再引导前后移动；米制估计仅在内参齐全时产出，距离字段须含 `focal_source`、有效内参、裁剪/缩放记录与距离定义；无内参时报未知/相对深度；**估计内参≠已知内参，禁重复换算**（EXIF 毫米焦距须换算为像素焦距后使用，已换算的不得再次缩放） | 每张图必产米制距离；单个数值当作实测 |
| R5 | 光向扇区 + 光质 + 歧义标注 | 保留多个假设：记录阴影、亮暗分布、眼神光等可见线索，输出可审查解释（如“相机左前上方主光的可能性较高，同时存在环境补光”）；单图不足以排除多灯、反射面、后期处理时不强行定一个方向；VLM 解读 + 不确定性标注；DSINE 已排除 | 精确灯位/灯距；角度数值 |
| R6 | 风格标签（VLM 解读） | Qwen3-VL-2B 作语义基线：风格、场景、可见线索与拍摄建议；VLM **只能写入白名单字段**（风格标签、场景标签、光照假设、自然语言指导），由 schema 与校验器强制，**不只靠提示词**；不能回写几何坐标、模型分数或距离真值字段 | VLM 生产坐标、补齐不可见关节、编造距离 |
| R7 | bundle 导出（人工审核后） | 带 provenance（模型 id + revision + 事实摘要 + synthetic/real + 人工审核状态）；三层表述：**观测证据层—模型估计层—拍摄建议层**；版本化映射比较共有语义关节，缺失语义不造点；生产失败显式“不可用/未知”，**禁静默 fake** | 未经人工审核的自动入库 |
| R8 | App 导入/选择姿势 + 场景确认 | 用户可导入姿势、可选择姿势；场景由**用户确认**；契约字段 `scene_source` 区分四种来源：**用户选择 / 本地模型 / 主机结果 / 未知**；v1 **不含自动场景识别**（列为未完成项，见 §5） | v1 自动场景识别 |
| R9 | 端侧实时 33 点 + 模板匹配 + 引导叠加 | 手机 MediaPipe Pose（Lite/Full 由实测选择）；姿势反馈走高频本地路径（CameraX 最新帧策略，推理结果带时间戳，过时结果不覆盖当前画面）；**LAN 不进实时姿势反馈**，只作导入/同步/单张分析；手机只运行 Pose 时，不把“手指弯曲正确”“眼睛看向正确位置”显示为已自动验证 | 手机端手指/视线自动验证（未运行对应模型时） |

## 4. 诚实边界（写进产品里，不许夸大）

1. 单张照片的拍摄距离是**估计**，永远带方法与置信度；EXIF 无焦距时降级为“景别 + 人体占比”描述；不知道内参时可输出明确标注的模型估计、相对深度或未知，**不能只把一个不可靠数值扩成区间就称为可靠距离**。
2. 视线给落区，不给精确注视点；侧脸/墨镜/低头/眼部像素不足时标“不可判”或保留人工标注/未知。
3. 光向给扇区 + 置信度；多光源/柔光箱场景标歧义；保留多个假设。
4. 手部遮挡时关节角标低置信或缺失，不许编；手部/眼姿/光向**无数值准确率门槛**，以独立记录、控制样本、拒答行为验收。
5. 所有“复刻指导”文案标注：按估计值复刻，需现场微调。
6. 2D 角是投影角；MediaPipe Pose 的 `world_landmarks` 是以髋部中点为原点的身体坐标，**其 z 值不是相机到人的距离**；手部 world 坐标以手中心为原点，**不能未经验证就与姿态 world 坐标拼接**。
7. 固定模型、固定随机种子、重复运行得到相同坐标，只能说明可重复，不代表坐标是真实值；确定性角度计算也可能是在错误关键点上精确算出一个错误角度。

## 8. 验收原则

1. 量化验收门槛：**待业主批准测试规格时固定**。GPT 两轮审核均未实际交付数值门槛，本文档不自造数值。
2. 20 张校准照片**不能同时充当调参集和独立验收集**；调参与独立验证必须分开。
3. 手部/眼姿/光向无数值准确率门槛，以独立记录、控制样本、拒答行为验收；眼姿和光向验收须拍摄有已知注视方向、已知灯位的控制样本，**两个模型同意同一个错误不算真值**。
4. **全拒答≠验收通过**：拒答行为本身须验收（该拒答时拒答、该回答时回答），不能以全部拒答冒充通过。
5. 3D 模块：2D 重投影吻合只能说明投影吻合，不能证明隐藏关节、手掌朝向和真实三维角度正确；可作对照，不能凭“看起来像”获得事实层资格。
6. 每阶段退出标准见 `03-execution-plan.md`；每阶段须业主点头方可进入下一阶段。

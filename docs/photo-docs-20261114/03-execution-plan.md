# 拍照双项目执行方案 v1（初稿）

> 状态：**初稿，待业主批准**。执行状态 HOLD；N2B1P 门禁保持硬停。
> 本方案只规定“批准后按什么顺序、什么标准执行”，**不构成执行授权**。路线定稿与业主拍板之前：不跑模型、不读真实照片、不改门禁、不合并、不部署。
> 技术共识状态：Muse 与 ChatGPT「Ai相机」GPT 两轮审核已形成技术共识（CONFIRMED）；业主批准待定（PENDING）。
> 量化验收门槛：GPT 两轮均未实际交付数值门槛，一律写“待业主批准测试规格时固定”，不得自造数值。

## 1. 门禁与执行规则

### 1.1 硬停规则

1. N2B1P 外部审查硬停**保持**，本次不建议解封；门禁简化或维持，待业主拍板（事项 #1）。
2. 在业主逐项批准之前：不跑模型、不读真实照片、不改门禁、不合并 PR、不部署、不下载权重。
3. 每阶段开始前须业主点头；每阶段结束须业主验收方可进入下一阶段。
4. 模型下载逐项批准：精确 revision、大小、SHA-256、许可证、删除方式，沿用 `OWNER_INPUTS_REQUIRED.md` 的批准表格式。
5. 照片不入库、权重不入库；本地优先；事实先于解读；VLM 不生产姿势；人工审核后导出；证据留存；来源追踪；可回滚。
6. 旧授权有到期信息，不能直接续用；“仓库内无记录”的事项按无记录表述，不作绝对断言。

### 1.2 阶段顺序原则

**把手机最小性能验证提前，把 LAN 放到离线拍摄闭环之后**——避免在整理大量库条目、维护一串 LAN PR 之后，才发现旧手机的实际体验不成立。

```
手机最小性能验证（Stage 0）
  → 主机基线抽取（Stage 1，20 张校准照片）
  → 离线拍摄闭环（Stage 2）
  → LAN 增强（Stage 3）
  ∥ 3D 实验模块（并行实验轨道，证据门控，不阻塞主线）
```

## 3. 升级评估流程（RTMW / DA3 / 量化 8B / 视线增强 / 标定候选）

每项升级独立走以下流程，全部通过方可进入默认栈：

## 4. 验收标准

### 4.1 通用规则

1. 量化验收门槛：**待业主批准测试规格时固定**。GPT 两轮审核均未实际交付数值门槛，本方案不自造数值。
2. 每阶段退出标准见 §2；每阶段须业主点头方可进入下一阶段。
3. 所有验收须留证据（记录、截图、日志、实测数字），不许只报结论。

### 4.2 分项验收方法

| 验收对象 | 方法 | 不接受 |
|---|---|---|
| 姿势事实 | 20 张校准集 + 业主抽检；逐点置信度/可见性完整 | 只报“跑通了”无记录 |
| 手部 | 独立记录；小手/遮挡/握物单独验证；冲突双候选审查记录 | 数值准确率门槛（无）；平均坐标 |
| 眼姿 | 控制样本：已知注视方向的摆拍；拒答行为验收 | 模型间一致即正确；数值准确率门槛（无） |
| 光向 | 控制样本：已知灯位的摆拍；档位一致性（人工标注集）；多假设记录 | 角度数值；模型间一致即正确 |
| 距离 | 构图闭环验收（画面占比/裁切匹配）；米制估计仅内参齐全时，以带真值测试集实测 | 单个数值当作实测；无内参报米数 |
| 3D 实验 | 已知角度或独立多视角参考；分姿态类别记录 | 2D 重投影吻合即正确；“看起来像” |
| 端侧实时 | 真机实测：延迟、发热、GPU delegate 兼容性、失败模式 | 旧机型/旧版本数据外推 |
| LAN | 真机配对 + 端到端真实分析 + 离线降级 | 代码存在即通过 |

### 4.3 边界规则（硬性）

1. **20 张校准照片不能同时充当调参集和独立验收集**；调参与独立验证必须分开，独立验收集须另行约定。
2. **手部/眼姿/光向无数值准确率门槛**，以独立记录、控制样本、拒答行为验收。
3. **全拒答≠验收通过**：拒答行为本身须验收（该拒答时拒答、该回答时回答）。
4. 眼姿和光向不以“模型之间一致”作为正确性验收；两个模型同意同一个错误不算真值。
5. 固定模型、固定随机种子下的可重复性不等于真实性；验收须以独立证据为准。

## 5. GPU 全局租约

### 5.1 原则：串行占有资源

串行调用还不够，必须串行占有资源。“两个 HTTP 请求没有并发”不等于“两个模型没有同驻显存”。须建立跨 NPI、App LAN 分析、Ollama、头像项目的**全局 GPU 租约**：

1. GPU 作业统一排队；每次模型阶段结束确认卸载，下一阶段才取得租约。
2. 每次作业开始前确认显存空闲；作业结束确认卸载（Ollama `keep_alive: 0` 可请求立即卸载，或 `ollama stop`；防止 Ollama 残留占用）。
3. 窗口结束前能够保存状态并停止；不能让 LAN 请求绕过排班。
4. CPU 工作（图像整理、校验、人工审阅）可独立进行，不占租约；主机 MediaPipe CPU 路径不占 GPU 租约。

### 5.2 窗口与峰值策略

- 窗口：每天 02:00–10:00；工作日另加 14:00–19:00；周末白天不空闲。
- 峰值策略：**整卡观测峰值不超过 10GiB**，给系统和波动预留约 2GiB。这是项目策略，不是任何模型的公开显存结论。
- 遇到 OOM：降低输入预算、切小模型或结束该能力；不要以长期占用或超窗运行硬扛。
- 排班：姿势 GPU 实验与头像项目（ComfyUI）同抢窗口，须统一排班；Grok 排班待回（事项 #5）。

### 5.3 租约覆盖范围

| 作业方 | 租约内作业 | 备注 |
|---|---|---|
| NPI（主机抽取） | Qwen3-VL-2B 解读、DA3（升级后）、RTMW（升级后）、3D 实验模块 | MediaPipe 主机 CPU 路径不占租约 |
| App LAN 分析 | 主机侧单张分析（service.py） | 不绕过排班；窗口外只读/降级 |
| Ollama | qwen3.5 / Qwen3-VL 服务 | `keep_alive: 0` / `ollama stop` 防残留 |
| 头像项目 | ComfyUI 出图 | 同一窗口，统一排班 |

## 6. 契约字段清单（Schema v1 落地时须覆盖）

| 字段/规则 | 要求 |
|---|---|
| 三层表述 | 每条输出标注所属层：观测证据层 / 模型估计层 / 拍摄建议层 |
| 原生拓扑 | 保留各模型原生拓扑；版本化映射比较共有语义关节；缺失语义不造点 |
| 手部冲突 | 保留双候选并触发审查；保留对应人物、左右手、裁剪图返回原图的变换 |
| VLM 白名单 | VLM 只能写入白名单字段（风格标签、场景标签、光照假设、自然语言指导）；由 schema 与校验器强制 |
| 距离字段 | `focal_source`、有效内参、裁剪/缩放记录、距离定义；估计内参≠已知内参，禁重复换算 |
| `scene_source` | 用户选择 / 本地模型 / 主机结果 / 未知（四值必一） |
| 视线三字段 | 头部朝向 / 眼睛相对相机的方向 / 画面内可能关注的区域，各可独立未知 |
| provenance | 模型 id + revision + 事实摘要 + synthetic/real + 人工审核状态 |
| 失败状态 | 显式“不可用/未知”，禁静默 fake；合成数据模式须诚实标注 |

# 拍照双项目可行性报告 v1（初稿）

> 状态：**初稿，待业主批准**。本文档只报告可行性结论，不授权执行。
> 技术共识状态：Muse 与 ChatGPT「Ai相机」GPT 两轮审核已形成技术共识（CONFIRMED）；业主批准待定（PENDING）；执行状态 HOLD；N2B1P 门禁保持硬停。
> 证据原则：代码许可 ≠ 权重许可 ≠ 人体参数模型许可 ≠ 数据集许可，分层登记；证据与推断分开；未核实处标注“未核实/待确认”；无发表来源的性能数字写“未实测/无公开数据”，不编造。许可证登记全文见 `04-license-register.md`。

## 1. 结论总览

1. **v1 基线栈可行**：主机 MediaPipe Pose Full（33 点，CPU 路径）+ 按需 Hand/Face + Qwen3-VL-2B 语义解读 + 默认关闭的 OpenVINO gaze 可选增强；手机 MediaPipe Pose + 本地规则排序；LAN 只作导入/同步/单张分析。基线不依赖任何未闭合许可缺口。
2. **升级项各凭独立证据**：RTMW 133 点、DA3 Metric-Large、量化 8B VLM、3D 实验模块均不进入 v1 默认栈，须逐项凭许可证闭合 + 实测 + 增益确认后升级。**许可通过≠进入默认栈**。
3. **性能全部待实测**：没有任何模型在目标硬件（RTX 4070 SUPER 12GB + Windows / OnePlus 7 Pro）上的实测数据；第三方估计互相冲突，一律不作结论。
4. **可观测边界已收敛**：距离、视线、灯位均有明确的“不可判/未知”状态与拒答行为；手部/眼姿/光向无数值准确率门槛。
5. **GPT 第一轮裁决**：总体方向有条件通过，但不应按原表述直接解封执行；执行状态 HOLD，门禁保持。GPT 未能独立读取两仓代码（连接认证失败），其评审按 Muse 交接的仓库事实处理，不算独立代码审计结论。终轮审核后形成本报告所依据的技术共识（Muse 已逐字核对终轮原文，见 `05-review-record.md` §6）。

## 2. 逐组件裁决

### 2.1 主机基线（v1 默认栈）

| 组件 | 裁决 | 依据与边界 |
|---|---|---|
| MediaPipe Pose Full（33 点，主机） | **通过，v1 基线** | 官方任务输出 33 点；权重 Apache-2.0（模型卡，见登记表）。**原生 Windows 主机按 CPU 路径设计**（MediaPipe Python GPU 支持仅 Ubuntu）；GPU 全局租约只覆盖 Qwen3-VL-2B 等 GPU 模型。主机 CPU 吞吐量未实测，待业主拍板事项 #9 决定是否接受此基线。`world_landmarks` 为髋部原点身体坐标，z 值不是相机距离 |
| MediaPipe Hand Landmarker（按需细化） | **条件通过** | 每手 21 点；只作条件式手部细化器，**不应对所有照片无条件覆盖**其他模型的手点；小手、遮挡、握物须单独验证；冲突时保留双候选触发审查，不平均坐标；须保留对应人物、左右手及裁剪图返回原图的变换 |
| MediaPipe Face Landmarker（脸部几何） | **通过（仅作眼部几何输入）** | 可给人脸与虹膜相关关键点；**虹膜跟踪不推断人在看哪里**（MediaPipe 官方说明），不能直接等同 gaze estimator；可作眼部几何输入与眼部可见性检查 |
| Qwen3-VL-2B（语义解读基线） | **通过，基线而非准确性保证** | 官方模型许可 Apache-2.0；可做风格、场景、可见线索与拍摄建议；**不能生产坐标、补齐不可见关节、替深度模型编造距离**；只能写入白名单字段（由 schema 校验器强制）。“权重在磁盘上”不等于图片输入链路已运行成功——本机图片推理链路未实测。2B 作基线的理由是降低集成变量 |
| OpenVINO gaze-estimation-adas-0002（可选增强，默认关闭） | **条件通过** | 接收左右眼图与头部姿态，输出视线方向向量，**不是实际注视点**；仅在“大且清楚的脸部裁剪”上作方向分类基线；小脸、墨镜、闭眼、强侧脸拒答；预训练权重 Apache-2.0（Open Model Zoo 许可）；模型库已弃用/维护模式，**须冻结资产本地存档**；其内部验证留出对象仅 2 人，平均误差不可外推为人像精度；不阻塞首版 |

| Gaze-LLE（视线增强候选） | **候选，未核实** | 画面内目标落区属另一项任务，可后续作对照；**decoder checkpoint 许可未核实**；未进入默认栈 |

## 3. 许可证登记摘要

分层登记全文见 `04-license-register.md`。摘要：

- **已核实通过**：MediaPipe 任务权重（模型卡 Apache-2.0，逐资产登记）；OpenVINO Model Zoo（Apache-2.0，须冻结存档）；DA3METRIC-LARGE（Apache-2.0，锁定具体资产）；Qwen3-VL-2B（Apache-2.0）；SMPL-X 条款原文（含非商业艺术项目，单用户、禁分发）；TinyCLIP（指定官方权重页 MIT 声明）；GeoCalib（权重 CC BY 4.0 正文 + 代码 Apache-2.0）；MoGe-2（指定官方权重页 MIT 声明）。
- **未闭合**：RTMW 权重；HaMeR checkpoint；Gaze-LLE decoder checkpoint；SMPLer-X checkpoint。
- **已排除**：DSINE、MobileCLIP2、YOLO-pose、L2CS-Net、Sapiens/Sapiens2。
- **规则**：许可通过≠进入默认栈；每个部署资产须记录下载 URL、版本、SHA-256、对应模型卡与许可快照；结论只落到已选资产，不写成“今后所有同类模型天然都一样”。

## 6. 风险与开放问题

1. **Grok Bot 至今零回复**：主机实况（两仓本地 HEAD/未提交状态、LAN 服务启动冒烟、Python 环境决策）、App 对账（T3–T17 与 main 差异清单）、GPU 排班三项任务无人接；是否催，待业主拍板（事项 #5）。
2. **App 侧对账未知**：T3–T17 的 15 个 stacked draft PR 与 main 的差异未对账；消费端能力边界不清。
3. **许可证缺口**：RTMW 权重、HaMeR checkpoint、Gaze-LLE decoder checkpoint、SMPLer-X checkpoint 均未闭合；升级项全部被门控。
4. **性能零实测**：见 §4 全部 12 项；任何“能跑”结论都须实测后才成立。
5. **GPT 评审边界**：GPT 未能独立读取两仓代码与指定 PR，仓库事实按 Muse 交接处理；代码审计未完成，见 `05-review-record.md`。
6. **20 张校准照片**：来源/目录与 EXIF 授权待业主提供；且 20 张不能同时充当调参集和独立验收集。
7. **量化验收门槛**：GPT 两轮均未实际交付数值门槛，待业主批准测试规格时固定；本文档不自造数值。
